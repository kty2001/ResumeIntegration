# 07. 사람인·잡코리아 DOM 현장 조사 (2026-10-13)

> 로그인 상태의 이력서 작성 페이지를 Claude in Chrome으로 읽기 전용 조사(구조만 수집, 입력값·개인정보 미기록). 섹션 펼치기('추가'·학력 구분 선택)만 수행하고 저장은 하지 않음

## 1. 요약

| 항목 | 사람인 | 잡코리아 |
|---|---|---|
| 작성 페이지 | `/zf_user/member/resume-manage/write?template_cd=1` | `/User/Resume/Write` |
| 이력서 관리 | `/zf_user/resume/resume-manage` | `/User/ResumeMng` |
| 프레임워크 | jQuery 1.11 + jQuery UI (React·Vue 아님) | jQuery 1.10 (React·Vue 아님) |
| 폼 구성 | 섹션별 '추가'·'수정하기' → 입력 → **섹션별 '저장'** | 한 페이지 폼(입력란 161개 미리 존재), 섹션은 메뉴로 표시 |
| 라벨 연결 | `label[for]` (id에 시각값 접미사: `userNm_1791…`) | `label[for]` 150/161 |
| 드롭다운 | 기본 `<select>` | **`<select>` 0개, 커스텀 드롭다운 14개 (ARIA 미준수)** |
| 날짜 | 텍스트 + 선택형 달력. 연월 `placeholder=YYYYMM`·`maxlength=6`, 생년월일 `maxlength=8` | 텍스트, placeholder 예시값(`1988.03.01`, `2016.03`) |
| 반복 항목 '추가' | 텍스트 버튼('추가') | 텍스트 버튼('추가', 'OO 추가') |
| iframe | 없음(보이지 않는 about:blank 2개) | 없음 |
| 자기소개서 | '추가' → 선택 모달('직접 입력하기') → 제목 input + 내용 textarea (`label[for]`) | 템플릿으로 생성: 제목 input(`label[for]`) + 내용 textarea(빈 `label for=""`), 글자수 표시 있음 |
| 자동 저장 | 확인 안 됨 (`onbeforeunload` 이탈 확인만) | **최초 작성 페이지에서 5분마다 자동 임시저장** |

## 2. 사람인

### 2.1 구조
- 섹션: 기본 정보(인라인 '수정하기'), 학력(학력 구분 select로 입력란 표시), 경력·스킬·My Career('추가'), 경험/활동·자격/어학/수상·포트폴리오·경력기술서·자기소개서·취업 우대사항(상단 메뉴로 섹션 추가)
- 기본 정보: 이메일·휴대폰·주소는 `readonly`(회원 정보·주소 검색 연동) → 현재 수집 규칙상 제외, 이름·생년월일·전화번호만 입력 가능
- 학력: 대학구분·졸업여부 `<select>`, 학교명(자동완성 검색, 직접 입력 허용), 전공, 입학·졸업년월(`YYYYMM`). 졸업여부 select는 라벨 텍스트가 비어 있고 첫 선택지('졸업여부 *')가 라벨 역할
- 경력: 회사명(자동완성 검색 + 숨은 회사 코드), 입사·퇴사년월(`YYYYMM`), 재직중 checkbox, 직무(선택 레이어 버튼형), 근무부서, 직급/직책, 담당업무 textarea, 연봉·근무지역 등은 추가 버튼으로 표시
- 취업 우대사항: 보훈·병역·고용지원금 checkbox, 병역 select·입대/제대년월, 장애등급 select, 민감정보 수집 동의 checkbox

### 2.2 범용 전략 적합성
- 라벨·select·날짜 형식 신호(placeholder·maxLength): **현재 매핑·형식 변환 규칙으로 대응 가능**
- '추가' 버튼 휴리스틱: 인식됨. 단 섹션별 '저장'을 눌러야 다음 블록 추가 가능할 수 있음(미확인, 저장 미수행)
- 학습 규칙: fingerprint에 id 포함 → 사람인 id는 페이지마다 시각값 접미사가 바뀌어 **학습 규칙 재사용 불가 가능성**
- 섹션별 저장 구조: 자동 입력 후 사용자가 섹션마다 '저장'을 눌러야 함 → 사이드 패널 안내 필요

### 2.3 열람 페이지
- 조사 계정의 이력서는 파일(PDF) 이력서 → 열람 페이지에 라벨-값 구조 없음(PDF 뷰어). 작성형 이력서의 열람 구조는 미확인

## 3. 잡코리아

### 3.1 구조
- 기본 정보: 이름·생년월일·이메일(`type=email`)·전화번호·휴대폰번호 text, 주소는 `readonly`(검색 연동), 성별은 커스텀 드롭다운
- 학력: 학교구분 커스텀 드롭다운 + 학교명(검색형, name 없음)
- 경력: 회사명(자동완성 + 숨은 코드), 부서명, 입사·퇴사년월, 재직중, 직급/직책 커스텀 드롭다운, 직급 radio 21개, 직책 radio 16개, 연봉, 담당업무 textarea
- 인턴·대외활동, 교육, 자격증, 수상, 해외경험, 어학(구분·외국어명·공인시험·급수 등 커스텀 드롭다운), 포트폴리오(URL·파일), 병역·장애·고용형태 커스텀 드롭다운
- 반복 항목 name 규칙: `Career[c0].CSYM`, `Social[N_N].Act_Start_YM` 등

### 3.2 커스텀 드롭다운 (ARIA 미준수)

```html
<div class="dropdown dropdown-profile-sex is-label">
  <div class="label" aria-hidden="true">성별 *</div>
  <button type="button" class="button buttonChoose" aria-haspopup="true"><span>남자</span></button>
  <div class="list hidden" aria-hidden="true">
    <ul><li><button type="button" data-value="…"><span>남자</span></button></li> …</ul>
  </div>
  <input type="hidden" name="UserInfo.M_Gender">
</div>
```

- 14개 중 `aria-haspopup` 있는 것 3개(값 `true`), 나머지는 ARIA 속성 없음. `role=combobox|listbox|option` 0개
- 현재 수집 대상(`[role=combobox]:not(input)`, `button[aria-haspopup=listbox]`)에 해당하지 않고, 값은 `type=hidden`이라 수집 제외 → **성별·학교구분·병역·어학 등 선택 항목 입력 불가**
- 라벨은 `<label>`이 아닌 `aria-hidden` div

### 3.3 확장 프로그램 실제 동작 (사용자 툴바 클릭)
- '이 페이지에서 가져오기': 4개 인식(이름·생년월일·이메일·휴대폰). 성별 등 커스텀 드롭다운은 미인식
- '작성': 입력 완료 7 · 확인 필요 0 · 해당 없음 7. 커스텀 드롭다운은 수집 대상이 아니어서 결과 목록에도 나타나지 않음
- 주의: 최초 작성 페이지는 5분마다 자동 임시저장 → '작성' 후 저장하지 않고 두면 채운 값이 임시저장될 수 있음 (이번 조사에서는 저장 전 자동 저장 타이머 중지 후 이탈)

## 4. 결론·후속 제안

| 항목 | 판단 | 제안 |
|---|---|---|
| ARIA 미준수 커스텀 위젯 | **필요** (잡코리아 선택 항목 전부) | 범용 패턴 추가: 버튼(`aria-haspopup` 유무 무관) + 형제 목록(`ul li button`·`li`) + 숨은 input을 가진 컨테이너를 드롭다운으로 수집, 라벨은 컨테이너 안 텍스트. 선택지 클릭 후 숨은 input 값·버튼 표시 텍스트로 검증 |
| 달력 탐색 클릭 | **불필요** | 두 사이트 모두 날짜를 텍스트로 직접 입력 가능 (달력은 보조) |
| '추가' 버튼 휴리스틱 | 적합 | 사람인 섹션별 저장 필요 여부는 저장 가능한 테스트 계정에서 확인 |
| 날짜·전화번호 형식 | 적합 | 사람인 `YYYYMM`·`maxlength=8`, 잡코리아 예시값 placeholder 모두 기존 규칙 대응 |
| 학습 규칙 fingerprint | 위험 | 사람인 id 시각값 접미사 → fingerprint에서 숫자 접미사 정규화 또는 name 우선 검토 |
| 빈 텍스트 라벨 | 보완 | 사람인 졸업여부 select: 첫 선택지 placeholder 텍스트를 라벨 후보로 사용, 잡코리아 자기소개서 textarea: 빈 `label for=""` → 주변 제목 사용 확인 |
| 자동 임시저장 | 안내 | 잡코리아는 '작성' 후 자동 임시저장될 수 있음 → 사이드 패널 안내 문구 검토 |
| 섹션별 저장(사람인) | 안내 | '작성' 후 섹션별 '저장' 필요 안내 |
| 열람 페이지 가져오기 | 보류 | 사람인 파일 이력서는 대상 아님, 작성형 열람 페이지는 미확인 → 범용 `readPairs`는 작성형 이력서 보유 계정에서 재조사 후 결정 |
| 연동 사이트 추천 URL | 확정 | 사람인 `https://www.saramin.co.kr/zf_user/resume/resume-manage`, 잡코리아 `https://www.jobkorea.co.kr/User/ResumeMng` (이력서 번호가 URL에 들어가는 수정 페이지 대신 관리 페이지) |
| 사전 보완 | 일부 | 잡코리아 '휴대폰번호'·'전화번호', 사람인 '입사년월'·'퇴사년월'·'입학년월'·'졸업년월'·'직급/직책'·'근무부서' 등 라벨 확인 후 사전 반영 여부 검토 |

## 5. 미확인
- 사람인: 섹션 저장 후 같은 섹션 '추가' 동작, 작성형 이력서 수정 페이지(`res_idx`)와 열람 페이지 구조, 희망근무조건(`/person-attr`) 화면
- 잡코리아: 기존 이력서 수정 페이지(`IsEditPage`) 구조·자동 저장 여부, 열람 페이지 구조, 학교명 검색 레이어 동작
- 두 사이트 모두 스크립트 이벤트(`isTrusted=false`) 거부 여부 (커스텀 드롭다운 구현 시 확인)
