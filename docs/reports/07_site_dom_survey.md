## 2. 사람인

### 2.1 구조
- 섹션: 기본 정보(인라인 '수정하기'), 학력(학력 구분 select로 입력란 표시), 경력·스킬·My Career('추가'), 경험/활동·자격/어학/수상·포트폴리오·경력기술서·자기소개서·취업 우대사항(상단 메뉴로 섹션 추가)
- 기본 정보: 이메일·휴대폰·주소는 `readonly`(회원 정보·주소 검색 연동) → 현재 수집 규칙상 제외, 이름·생년월일·전화번호만 입력 가능
- 학력: 대학구분·졸업여부 `<select>`, 학교명(자동완성 검색, 직접 입력 허용), 전공, 입학·졸업년월(`YYYYMM`). 졸업여부 select는 라벨 텍스트가 비어 있고 첫 선택지('졸업여부 *')가 라벨 역할
- 경력: 회사명(자동완성 검색 + 숨은 회사 코드), 입사·퇴사년월(`YYYYMM`), 재직중 checkbox, 직무(선택 레이어 버튼형), 근무부서, 직급/직책, 담당업무 textarea, 연봉·근무지역 등은 추가 버튼으로 표시
- 취업 우대사항: 보훈·병역·고용지원금 checkbox, 병역 select·입대/제대년월, 장애등급 select, 민감정보 수집 동의 checkbox

### 2.2 범용 전략 적합성
- 라벨·select·날짜 형식 신호(placeholder·maxLength): **현재 매핑·형식 변환 규칙으로 대응 가능**
- '추가' 버튼 휴리스틱: 인식됨. 단 섹션별 '저장'을 눌러야 다음 블록 추가 가능할 수 있음(미확인, 저장 미수행)
- 학습 규칙: fingerprint에 id 포함 → 사람인 id는 페이지마다 시각값 접미사가 바뀌어 **학습 규칙 재사용 불가 가능성**
- 섹션별 저장 구조: 자동 입력 후 사용자가 섹션마다 '저장'을 눌러야 함 → 사이드 패널 안내 필요

### 2.3 열람 페이지
- 조사 계정의 이력서는 파일(PDF) 이력서 → 열람 페이지에 라벨-값 구조 없음(PDF 뷰어). 작성형 이력서의 열람 구조는 미확인

## 3. 잡코리아

### 3.1 구조
- 기본 정보: 이름·생년월일·이메일(`type=email`)·전화번호·휴대폰번호 text, 주소는 `readonly`(검색 연동), 성별은 커스텀 드롭다운
- 학력: 학교구분 커스텀 드롭다운 + 학교명(검색형, name 없음)
- 경력: 회사명(자동완성 + 숨은 코드), 부서명, 입사·퇴사년월, 재직중, 직급/직책 커스텀 드롭다운, 직급 radio 21개, 직책 radio 16개, 연봉, 담당업무 textarea
- 인턴·대외활동, 교육, 자격증, 수상, 해외경험, 어학(구분·외국어명·공인시험·급수 등 커스텀 드롭다운), 포트폴리오(URL·파일), 병역·장애·고용형태 커스텀 드롭다운
- 반복 항목 name 규칙: `Career[c0].CSYM`, `Social[N_N].Act_Start_YM` 등

### 3.2 커스텀 드롭다운 (ARIA 미준수)

```html
<div class="dropdown dropdown-profile-sex is-label">
  <div class="label" aria-hidden="true">성별 *</div>
  <button type="button" class="button buttonChoose" aria-haspopup="true"><span>남자</span></button>
  <div class="list hidden" aria-hidden="true">
    <ul><li><button type="button" data-value="…"><span>남자</span></button></li> …</ul>
  </div>
  <input type="hidden" name="UserInfo.M_Gender">
</div>
```

- 14개 중 `aria-haspopup` 있는 것 3개(값 `true`), 나머지는 ARIA 속성 없음. `role=combobox|listbox|option` 0개
- 현재 수집 대상(`[role=combobox]:not(input)`, `button[aria-haspopup=listbox]`)에 해당하지 않고, 값은 `type=hidden`이라 수집 제외 → **성별·학교구분·병역·어학 등 선택 항목 입력 불가**
- 라벨은 `<label>`이 아닌 `aria-hidden` div

### 3.3 확장 프로그램 실제 동작 (사용자 툴바 클릭)
- '이 페이지에서 가져오기': 4개 인식(이름·생년월일·이메일·휴대폰). 성별 등 커스텀 드롭다운은 미인식
- '작성': 입력 완료 7 · 확인 필요 0 · 해당 없음 7. 커스텀 드롭다운은 수집 대상이 아니어서 결과 목록에도 나타나지 않음
- 재확인(커스텀 드롭다운 대응 후, `f24bf77`): '작성' 입력 완료 8 · 확인 필요 0 · 해당 없음 7 (성별 추가), '가져오기' 결과 현재 이력서와 다른 항목 없음, 입력 후 열린 목록 없음
  - 스크립트 이벤트(`isTrusted=false`)로 성별 목록 열기·선택·닫기·숨은 input 갱신 모두 동작 (값 바꾼 뒤 원래 값 복원, 저장 안 함)
  - 화면에 보이는 커스텀 드롭다운 4개 중 패턴 해당은 성별 1개. 학교구분 2개는 숨은 input 없이 선택 시 학교 입력 폼을 전환하는 UI, 고용형태는 목록 안 checkbox 다중 선택형 → 미인식. 나머지 11개는 펼치지 않은 섹션 안: 패턴 해당 7개(활동구분·어학 구분·외국어명·점수 선택·회화능력·장애 등급·병역), 선택지가 비어 있는 2개(공인시험·급수, 외국어명 선택 후 채워지는 것으로 추정), 숨은 input이 형제가 아닌 직급/직책, 숨은 input 없는 군별/제대 계급
- 주의: 최초 작성 페이지는 5분마다 자동 임시저장 → '작성' 후 저장하지 않고 두면 채운 값이 임시저장될 수 있음 (이번 조사에서는 저장 전 자동 저장 타이머 중지 후 이탈)

|---|---|
| 자기소개서 | '추가' → 제목 input(`ResumeProfile[cN].Header`, `label.skip[for]` '제목', placeholder '항목 제목을 입력하세요.') + 내용 textarea(`…Contents`, 형제 `label.skip for=""` '내용', placeholder '해당내용을 입력하세요.'). 문항을 사용자가 직접 쓰는 자유형. '작성' 결과 제목·내용 모두 해당 없음, '자기소개서 추천' 없음(문항 텍스트가 placeholder뿐) |
| '작성' (신규 작성 페이지) | 입력 완료 7 · 해당 없음 10. 학력 블록이 2개가 되고 학교구분 미선택 블록에 학교명만 입력됨(사이트 경고 '학교구분을 선택해주세요') |
| 학교구분 | 선택 시 학력 입력 폼 전환(학교명 비워지고 입학·졸업년월·졸업상태·전공명·학점 표시). 선택 후 드롭다운은 숨은 input(`Schl_Type_Code`)이 버튼 형제가 아닌 목록 `div.list` 안에 있음 → 현재 커스텀 드롭다운 패턴과 불일치, 가져오기에서 누락 |
| 학교명·전공명 자동완성 | 학교구분 선택 후 동작. 표시 input은 name 없음, 저장 값은 숨은 `Schl_Name`·`School_Code`. 목록에서 고르지 않으면 바깥 클릭 때 값 비움, 목록 `div.list > ul > li > button`(ARIA 없음) 스크립트 클릭 시 숨은 값 설정 |
| 졸업상태 드롭다운 | 스크립트로 열기·선택 → 표시 텍스트·숨은 input 갱신 |
| 저장 필수 항목 | 희망직무·희망근무지(레이어 선택) 없으면 저장 불가 → '임시저장하기'는 가능, 임시저장본은 '미완성 이력서'로 `/User/Resume/Write` 재진입 시 복원 |
| 수정 페이지 `/User/Resume/Edit?RNo=N` | `IsEditPage=True`, 작성 페이지와 같은 한 페이지 폼(값이 보이는 입력란). 자동 임시저장은 `if (!IsEditPage)` 조건 → 수정 페이지에서는 없음. 가져오기: 학력 1건(학교명·입학·졸업연월·졸업상태·전공) 인식, 학교구분 누락. 인적사항은 확장 프로그램 값으로 '작성'한 값이라 미리 보기에 차이 없음 |
| 열람 페이지 `/User/Resume/View?rNo=N` | 인적사항 `div.item > div.label + div.value`, 요약 `div.summary > div.item > div.header + div.description(+ div.option)`, 희망근무조건 `table th[scope=row] + td`, 학력 `div.list-education > div.item` 안 `.term`·`.state`·`.name`·`.line`(라벨 없음) |

### 6.3 결론·후속 제안

| 항목 | 판단 | 제안 |
|---|---|---|
| 폼을 다시 그리는 select (사람인 학력구분, 잡코리아 학교구분) | **필요** | 입력 후 분리된(`isConnected=false`) 입력란이 있으면 다시 수집해 남은 항목 입력. select 값이 이미 같으면 이벤트 생략 |
| 같은 블록 안 같은 키 중복 (학력구분·대학구분) | **필요** | 중복 키를 다음 인덱스로 넘기지 않고 선택지가 매칭되는 입력란 하나만 배정 |
| 검색형 자동완성 (ARIA 없음, 학교명·전공명) | **필요** | 입력 후 나타나는 목록에서 일치 항목 클릭(기존 검색형 콤보박스 확장). 미선택 시 값이 지워지므로 실패 판정 |
| 잡코리아 커스텀 드롭다운 변형 | 보완 | 숨은 input이 목록 안에 있는 경우도 패턴에 포함 |
| 자유형 자기소개서 (제목 + 내용) | 보완 | 자기소개서 섹션의 제목 input·라벨 없는 textarea 쌍 → 문항·답변으로 입력 또는 추천 |
| 사람인 상세주소 | 보완 | 기본 주소가 readonly일 때 상세주소 입력란을 주소로 매핑하지 않음 |
| 사람인 수정 페이지 가져오기 | 안내 | 보기 모드라 empty → '섹션별 수정하기로 펼친 뒤 가져오기' 안내. 섹션당 1블록만 펼쳐져 반복 항목은 여러 번 필요 |
| 사람인 반복 항목 | 안내 | '저장' 후 '추가' 가능 → 사이드 패널 안내에 '섹션 저장 후 다시 작성' 추가 |
| 열람 페이지 가져오기 | 범용 부적합 | 잡코리아 인적사항·희망근무조건만 라벨-값 추출 가능, 반복 항목은 두 사이트 모두 라벨 없음 → 사이트별 어댑터 필요. 수정 폼 가져오기 보완 후 필요성 재판단 |
